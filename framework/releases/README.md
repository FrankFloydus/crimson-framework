# Addon release procedure

Each work commit gets its own addon ZIP and version tag. Start at `0.0.1` and increment the patch number numerically through `0.0.9999`. Check local and remote tags before selecting the next version. Keep published versions immutable. Confirm the next version scheme with the maintainer after `0.0.9999`.

1. Build the Godot 4.7 Windows x86-64 debug and release DLLs for the source going into the commit. Follow the [build and verification instructions](../README.md#build). Package the addon under `addons/crimson-framework/` in the archive. Include the extension descriptor, its UID, both Crimson DLLs, the `images/` folder, the `input/` presets and their referenced actions, and the redistribution notices. The standard addon ZIP carries Crimson binaries. Integrators stage the optional Steam runtime from Valve's SDK. Keep the SDK, its runtime DLL, development App ID files, build intermediates, editor caches, demo, and test data outside the ZIP. [Steamworks SDK setup](../vendor/README.md)
2. Save the archive as `releases/crimson-framework-0.0.x.zip`. Inspect its contents against the descriptor and stage it with the work it packages. Follow the [commit conventions](../AGENTS.md#git-conventions). After committing, create the annotated tag `v0.0.x` on that exact commit and record the full SHA, description, and relative ZIP link in [DEVLOG.md](../DEVLOG.md). Use `Pending publish` for the GitHub Release link until it has been verified.
3. Before pushing, audit the outgoing commits, tags, ZIPs, and log coverage. Push the branch and its release tags. Publish a GitHub Release for each pushed tag and attach the same ZIP from the tagged commit. Verify the remote tag resolves to the recorded SHA and the downloadable asset matches the committed ZIP.
4. Update the verified download links in DEVLOG.md and resolve the pending work-commit SHAs in [LOG.md](../LOG.md). Publish both logs in a single `docs:` follow-up commit with a descriptive body. Keep that follow-up limited to SHA and release-link bookkeeping. It gets no additional ZIP, tag, or DEVLOG entry because a commit's own SHA is only available after its content is fixed. Any separate work, including documentation changes, gets its own versioned release.
